# Сигнали

Сутрешен доклад и дневник на проблемите от **Обход** и **Мин Макс**.

- Всяка сутрин в 07:30 (българско време) събира сигналите, записва ги в дневника без повторения и пише кратък доклад с Claude.
- Сигнали от Обход: пропуснати обходи, „НЕ“ по чеклиста (висящи от 3+ обхода поред), забележки на AI по снимките.
- Сигнали от Мин Макс: аномалии от Mistral (дублирани/недоставени/подозрителни доставки, брак, липси, фантомна наличност) и реално свършили артикули.
- Нов и невъзложен сигнал, който изчезне, се затваря сам. Възложеният остава, докато човек не го затвори.
- Всяко възлагане се пази → в „Статистика“ се вижда кой вид проблем на кого отива — оттам излизат правилата за автоматично уведомяване.

## Railway Variables

| Име | Стойност |
|---|---|
| `OBHOD_MONGO_URI` | същото като `MONGO_URI` на Обход |
| `MINMAX_API_KEY` | същото като `API_KEY` на Мин Макс |
| `MINMAX_URL` | `https://minmaxai.up.railway.app` (по подразбиране) |
| `ANTHROPIC_API_KEY` | ключ за Claude API |
| `APP_PASSWORD` | парола за вход в страницата |
| `SESSION_SECRET` | дълъг случаен текст |
| `API_KEY` | (по желание) ключ за машинен достъп до `/api` с header `X-API-Key` |
| `REPORT_HOUR_LOCAL` / `REPORT_MINUTE_LOCAL` | час на доклада (по подразбиране 7 и 30) |
| `STUCK_DAYS` | от колко поредни „НЕ“ проблемът е висящ (по подразбиране 3) |

Собствените данни са в колекции `signali_problems`, `signali_reports`, `signali_owners` в базата на Обход. Колекциите на Обход само се четат.

## API (за бъдещо делегиране)

- `GET /api/report` — последният доклад
- `POST /api/run` — събери сигналите сега
- `GET /api/problems?status=open&source=&owner=&store=&type=&q=`
- `PATCH /api/problems/:id` — `{status, owner, action, priority, by}`
- `GET/POST/PUT/DELETE /api/owners` — отговорници
- `GET /api/stats?days=30` — статистика и кандидати за правила
